# BetaCountMessageTokensParams

## Properties

| Property | Required | Type | Description |
| :------- | :------: | :--- | :---------- |
| `messages` | Yes | array<[BetaInputMessage](./BetaInputMessage.md)> | Input messages.<br/><br/>Our models are trained to operate on alternating `user` and `assistant` conversational turns. When creating a new `Message`, you specify the prior conversational turns with the `messages` parameter, and the model then generates the next `Message` in the conversation. Consecutive `user` or `assistant` turns in your request will be combined into a single turn.<br/><br/>Each input message must be an object with a `role` and `content`. You can specify a single `user`-role message, or you can include multiple `user` and `assistant` messages.<br/><br/>If the final message uses the `assistant` role, the response content will continue immediately from the content in that message. This can be used to constrain part of the model's response.<br/><br/>Example with a single `user` message:<br/><br/>```json<br/>[{"role": "user", "content": "Hello, Claude"}]<br/>```<br/><br/>Example with multiple conversational turns:<br/><br/>```json<br/>[<br/>  {"role": "user", "content": "Hello there."},<br/>  {"role": "assistant", "content": "Hi, I'm Claude. How can I help you?"},<br/>  {"role": "user", "content": "Can you explain LLMs in plain English?"},<br/>]<br/>```<br/><br/>Example with a partially-filled response from Claude:<br/><br/>```json<br/>[<br/>  {"role": "user", "content": "What's the Greek name for Sun? (A) Sol (B) Helios (C) Sun"},<br/>  {"role": "assistant", "content": "The best answer is ("},<br/>]<br/>```<br/><br/>Each input message `content` may be either a single `string` or an array of content blocks, where each block has a specific `type`. Using a `string` for `content` is shorthand for an array of one content block of type `"text"`. The following input messages are equivalent:<br/><br/>```json<br/>{"role": "user", "content": "Hello, Claude"}<br/>```<br/><br/>```json<br/>{"role": "user", "content": [{"type": "text", "text": "Hello, Claude"}]}<br/>```<br/><br/>Starting with Claude 3 models, you can also send image content blocks:<br/><br/>```json<br/>{"role": "user", "content": [<br/>  {<br/>    "type": "image",<br/>    "source": {<br/>      "type": "base64",<br/>      "media_type": "image/jpeg",<br/>      "data": "/9j/4AAQSkZJRg...",<br/>    }<br/>  },<br/>  {"type": "text", "text": "What is in this image?"}<br/>]}<br/>```<br/><br/>We currently support the `base64` source type for images, and the `image/jpeg`, `image/png`, `image/gif`, and `image/webp` media types.<br/><br/>See [examples](https://docs.anthropic.com/en/api/messages-examples#vision) for more input examples.<br/><br/>Note that if you want to include a [system prompt](https://docs.anthropic.com/en/docs/system-prompts), you can use the top-level `system` parameter — there is no `"system"` role for input messages in the Messages API. |
| `model` | Yes | [Model](Model.md) |  |
| `system` | No | anyOf(2) | System prompt.<br/><br/>A system prompt is a way of providing context and instructions to Claude, such as specifying a particular goal or role. See our [guide to system prompts](https://docs.anthropic.com/en/docs/system-prompts). |
| `tool_choice` | No | [BetaToolChoice](BetaToolChoice.md) |  |
| `tools` | No | array<oneOf(4)> | Definitions of tools that the model may use.<br/><br/>If you include `tools` in your API request, the model may return `tool_use` content blocks that represent the model's use of those tools. You can then run those tools using the tool input generated by the model and then optionally return results back to the model using `tool_result` content blocks.<br/><br/>Each tool definition includes:<br/><br/>* `name`: Name of the tool.<br/>* `description`: Optional, but strongly-recommended description of the tool.<br/>* `input_schema`: [JSON schema](https://json-schema.org/) for the tool `input` shape that the model will produce in `tool_use` output content blocks.<br/><br/>For example, if you defined `tools` as:<br/><br/>```json<br/>[<br/>  {<br/>    "name": "get_stock_price",<br/>    "description": "Get the current stock price for a given ticker symbol.",<br/>    "input_schema": {<br/>      "type": "object",<br/>      "properties": {<br/>        "ticker": {<br/>          "type": "string",<br/>          "description": "The stock ticker symbol, e.g. AAPL for Apple Inc."<br/>        }<br/>      },<br/>      "required": ["ticker"]<br/>    }<br/>  }<br/>]<br/>```<br/><br/>And then asked the model "What's the S&P 500 at today?", the model might produce `tool_use` content blocks in the response like this:<br/><br/>```json<br/>[<br/>  {<br/>    "type": "tool_use",<br/>    "id": "toolu_01D7FLrfh4GYq7yT1ULFeyMV",<br/>    "name": "get_stock_price",<br/>    "input": { "ticker": "^GSPC" }<br/>  }<br/>]<br/>```<br/><br/>You might then run your `get_stock_price` tool with `{"ticker": "^GSPC"}` as an input, and return the following back to the model in a subsequent `user` message:<br/><br/>```json<br/>[<br/>  {<br/>    "type": "tool_result",<br/>    "tool_use_id": "toolu_01D7FLrfh4GYq7yT1ULFeyMV",<br/>    "content": "259.75 USD"<br/>  }<br/>]<br/>```<br/><br/>Tools can be used for workflows that include running client-side tools and functions, or more generally whenever you want the model to produce a particular JSON structure of output.<br/><br/>See our [guide](https://docs.anthropic.com/en/docs/tool-use) for more details. |
