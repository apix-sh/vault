# PromptCachingBetaMessage

## Properties

| Property | Required | Type | Description |
| :------- | :------: | :--- | :---------- |
| `content` | Yes | array<[ContentBlock](./ContentBlock.md)> | Content generated by the model.<br/><br/>This is an array of content blocks, each of which has a `type` that determines its shape.<br/><br/>Example:<br/><br/>```json<br/>[{"type": "text", "text": "Hi, I'm Claude."}]<br/>```<br/><br/>If the request input `messages` ended with an `assistant` turn, then the response `content` will continue directly from that last turn. You can use this to constrain the model's output.<br/><br/>For example, if the input `messages` were:<br/>```json<br/>[<br/>  {"role": "user", "content": "What's the Greek name for Sun? (A) Sol (B) Helios (C) Sun"},<br/>  {"role": "assistant", "content": "The best answer is ("}<br/>]<br/>```<br/><br/>Then the response `content` might be:<br/><br/>```json<br/>[{"type": "text", "text": "B)"}]<br/>``` |
| `id` | Yes | string | Unique object identifier.<br/><br/>The format and length of IDs may change over time. |
| `model` | Yes | [Model](Model.md) |  |
| `role` | Yes | string | Conversational role of the generated message.<br/><br/>This will always be `"assistant"`. Allowed values: assistant |
| `stop_reason` | Yes | anyOf(2) | The reason that we stopped.<br/><br/>This may be one the following values:<br/>* `"end_turn"`: the model reached a natural stopping point<br/>* `"max_tokens"`: we exceeded the requested `max_tokens` or the model's maximum<br/>* `"stop_sequence"`: one of your provided custom `stop_sequences` was generated<br/>* `"tool_use"`: the model invoked one or more tools<br/><br/>In non-streaming mode this value is always non-null. In streaming mode, it is null in the `message_start` event and non-null otherwise. |
| `stop_sequence` | Yes | anyOf(2) | Which custom stop sequence was generated, if any.<br/><br/>This value will be a non-null string if one of your custom stop sequences was generated. |
| `type` | Yes | string | Object type.<br/><br/>For Messages, this is always `"message"`. Allowed values: message |
| `usage` | Yes | allOf(1) | Billing and rate-limit usage.<br/><br/>Anthropic's API bills and rate-limits by token counts, as tokens represent the underlying cost to our systems.<br/><br/>Under the hood, the API transforms requests into a format suitable for the model. The model's output then goes through a parsing stage before becoming an API response. As a result, the token counts in `usage` will not match one-to-one with the exact visible content of an API request or response.<br/><br/>For example, `output_tokens` will be non-zero, even for an empty string response from Claude. |
